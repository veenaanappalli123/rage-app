## 2. Project Objective

The objective is to build a web application that allows users to upload documents, index their content, ask questions about those documents and receive answers grounded in retrieved source passages.

The application should support document management, configurable retrieval, source references, controlled failures and evaluation.

## 3. Corpus

The initial evaluation corpus is a technical handbook covering:

- Networking fundamentals
- Network protocols
- Network security
- Web application security
- Cryptography
- Network monitoring and incident response
- Cloud and distributed systems
- Security best practices

The application must also support documents uploaded by users rather than depending exclusively on this initial corpus.

## 5. Architecture

The application has two main processing phases.

### Indexing

1. The user uploads a document.
2. The backend validates the file.
3. Text is extracted.
4. The text is divided into chunks.
5. An embedding is generated for each chunk.
6. The chunks and associated metadata are stored in the vector database.

### Question Answering

1. The user submits a question.
2. The question is converted into an embedding.
3. Relevant chunks are retrieved.
4. The retrieved context is supplied to the language model.
5. The model generates a grounded response.
6. The backend validates the response.
7. The application displays the answer and source references.

## 8. Known Limitations

- Retrieval quality depends on corpus quality, chunking and embedding selection.
- Similarity scores are not equivalent to answer confidence.
- The language model can produce unsupported information if grounding and validation are insufficient.
- The initial corpus is a baseline and does not represent every possible user document.
- Evaluation metrics must be measured and compared across versions.
